Attendance & TMI Tools

Attendance is stored as exceptions only (T / U / E and TMI overrides) in attendanceEvents, plus one attendanceSessions record per class per day that says attendance was taken. Present is not stored. Every tool below works on a date range so it reads only what it needs.

One-time migration tools — already run, don't use these

These were run once when the new attendance model went live and are finished. Steps 1 and 2 each read every record in the old classAttendanceLogs collection — about 30,000 documents, over half the daily Firestore limit — so running one by accident can take the app offline for the rest of the day. Only use these if a migration genuinely needs redoing. Each asks for confirmation first.

Full backup of classAttendanceLogs including Present rows. ~30,000 reads.
Copies every T/U/E and override row into attendanceEvents under its new ID and builds a session record for every class-day that had attendance saved. ~30,000 reads.
Moves each TMI record to its one-per-student-per-period ID, merging any duplicates. Reads only TMI records.
Regroups TMI created while the week ran Monday–Sunday onto Wednesday–Tuesday weeks, recomputing minutes for the new grouping and carrying across time already served. Hand-picked date ranges and manually assigned TMI are left alone. Reads only TMI records and the absences in the range.

Attendance Coverage

Which classes have had attendance taken on each school day in a date range, based on the scheduled meeting days. Reads the session records for the range — not the attendance itself.

Clear Attendance by Date Range

Scan and delete absence records and "attendance taken" sessions within a date range, optionally for one teacher. TMI for every affected student is recalculated afterwards.

Recalculate TMI for a Date Range

Re-runs the TMI calculation for every TMI record whose period touches the range, from the absence records that exist now. Fixes records stuck at stale minutes and backfills a blank "Assigned By". Records with minutes already served are preserved, never deleted.

Merge Duplicate TMI Records

Finds a student listed twice for the same week on TMI Review or the Roster, and merges the pair into one record — keeping every sitting, adding up the minutes served, and holding on to any parent notification already sent. This happens when one record was written with the student's roster ID and another with only their A#, which used to produce two documents for the same week. Two records for genuinely different periods, or a hand-picked date range alongside a weekly record, are left alone — those are two real decisions, not a duplicate. Uses the date range above.

Fix Teacher Names on Attendance

Corrects attendance records that stored a staff member's full sign-in name where a surname belongs — dress-code entries used to do this, which made one person show up twice in the Teacher dropdown ("McCoy" and "ZACHARY MCCOY") and split their TMI between the two. Matches each one back to the staff list; anything that can't be matched has its teacher cleared, which is correct for a dress code since there is no class teacher. Affected students are recalculated so "Assigned By" catches up. Uses the date range above.

Refresh Cached Lists

Students, staff, parents, schedules, templates and PBL data are downloaded once per computer and then reused, which is what keeps daily reads low. Changes made inside P2MT refresh everyone automatically. Use this only after editing data directly in the Firebase console, which P2MT can't see — it tells every browser to re-download those lists on their next page load.
